# 潜词产品优化统一规划

日期：2026-06-09

> 本文档是潜词优化工作的单一规划源。原先分散在路线图、实施计划和讨论记录里的内容，应优先合并到这里，避免后续开发时出现多个版本的“计划”。

## 1. 产品定位

潜词是一款浏览器阅读辅助扩展，不是整页翻译工具，也不是重型背词平台。核心体验应保持轻：

> 用户在真实网页里阅读英文时，潜词安静地标出“可能需要看一眼”的词；不打断、不拖慢、不误伤页面，并且越用越懂用户。

本轮优化围绕八个目标展开：

- **可解释**：用户知道为什么某个词被标注、为什么某个词不再标注，以及如何撤销。
- **不卡顿**：长页面、SPA、动态内容、iframe、open shadow DOM 中仍保持流畅。
- **高兼容**：绝大多数普通网页可用；复杂页面安全降级，而不是硬撑到页面错乱。
- **联网可靠**：联网补查失败有明确原因、备用链路、退避重试和用户可见队列。
- **用户可控**：当前站点、当前页面、当前词都有轻量调整入口。
- **数据透明**：本地保存什么、什么时候联网、如何导出和清空，都让用户看得见。
- **尊重场景**：阅读、写作、搜索、技术文档、课程页面使用不同打扰策略。
- **可迁移**：用户能导出、备份、恢复自己的学习数据。

## 2. 当前项目实际

### 2.1 已具备能力

- `src/core/profile.ts` 已有 `feedbackSettings`、弱反馈模式、旧 profile 迁移和弱反馈重置能力。
- `src/options/main.ts` 已有标注策略面板、弱正反馈模式调节和弱反馈隐藏数量展示。
- `src/content/app.ts` 已将扫描改成节点级分片队列，并支持 `MutationObserver`、open shadow root 扫描和站点模式更新。
- `src/content/tooltip.ts` 已使用 Shadow DOM 隔离 tooltip 样式，并支持键盘关闭、外部点击关闭、焦点返回和非模态 dialog 语义。
- `src/manifest.ts` 已声明 `all_frames: true`，并加入 `alarms` 权限。
- `src/background/onlineDictionary.ts` 已有联网超时、错误分类、FreeDictionary 失败后的 `dictionaryapi.dev` 备用链路，以及 MyMemory 中文翻译。
- `src/storage/onlineLookupQueueStore.ts` 已有联网补查重试队列模型。
- `src/popup/main.ts` 已有站点模式控制、页面诊断、重新扫描、密度快捷调整和复制脱敏诊断信息。

### 2.2 仍缺关键闭环

- 联网重试队列已存在，但用户还看不到“哪些词在等重试、为什么失败、何时再试、如何清空”。
- 弱正反馈已可调，但还缺隐藏词明细、单词级恢复、“总是提醒我”和更自然的解释。
- 页面兼容已有技术底座，但缺长期兼容性测试矩阵、安全模式和问题站点反馈模板。
- 性能已有分片扫描，但缺预算指标、压力页面、长任务监控和趋势记录。
- 设置页功能增加后需要按用户任务重新分组，否则会变成扩展内部控制台。
- 在线释义来源还不够透明，尤其是词典 provider、机器翻译 provider、缓存结果和用户自定义释义之间的区别。

## 3. 外部依据与设计边界

联网核对后的外部约束如下：

- Chrome content scripts 的 `all_frames` 会让脚本注入匹配条件内的所有 frame；`match_about_blank` 和 `match_origin_as_fallback` 能覆盖更多相关 frame，但会扩大注入范围，应按课程页、文档预览等真实需求谨慎启用。参考：[Chrome content scripts manifest](https://developer.chrome.com/docs/extensions/reference/manifest/content-scripts)。
- Chrome `alarms` 可用于未来时间点或周期调度，但 alarm 不保证永久持久；service worker 启动时应检查并补建关键 alarm。参考：[Chrome alarms API](https://developer.chrome.com/docs/extensions/reference/api/alarms)。
- Chrome `storage` 适合 extension 页面、content script、service worker 共享数据；长期使用要考虑配额、迁移、清理、导入导出和 `storage.sync` 限制。参考：[Chrome storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。
- Chrome 扩展安全与隐私实践强调最小权限、最小数据收集、敏感信息不入日志；潜词应把“只发送被查单词，不发送整页内容”做成界面内可见承诺。参考：[Chrome extension security best practices](https://developer.chrome.com/docs/extensions/develop/security-privacy/stay-secure)。
- Web 性能最佳实践强调拆分长任务，让主线程及时响应用户交互；潜词 DOM 扫描必须坚持分片、预算、取消机制和首屏优先。参考：[web.dev Optimize long tasks](https://web.dev/articles/optimize-long-tasks)。
- Chrome Web Vitals 将 INP 作为交互响应指标之一；潜词在扫描、标注、tooltip 打开和重新扫描时都应避免制造长任务。参考：[web.dev INP](https://web.dev/articles/inp)。
- `MutationObserver` 是监听 DOM 变化的标准能力，但必须显式 `disconnect()`，并避免高频 mutation 触发重复扫描。参考：[MDN MutationObserver](https://developer.mozilla.org/docs/Web/API/MutationObserver)。
- Shadow DOM 的 open root 可通过 `element.shadowRoot` 访问，closed root 对外不可见；潜词只支持 open shadow root，不破解 closed shadow root。参考：[MDN attachShadow](https://developer.mozilla.org/en-US/docs/Web/API/Element/attachShadow)。
- WAI-ARIA tooltip 模式强调只读 tooltip 不应抢焦点；如果卡片包含按钮并允许焦点进入，更适合使用非模态 dialog 语义，并保留 `Escape` 关闭与焦点返回。参考：[WAI-ARIA Tooltip Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)。
- WCAG 2.2 对键盘可访问、焦点可见、目标尺寸等有明确要求；标注词、tooltip 按钮、popup 与 options 控件都应避免“只有鼠标能用”。参考：[WCAG 2.2](https://www.w3.org/TR/WCAG22/)。
- MyMemory API 明确存在 usage limits 和服务条款；潜词必须做限流、退避、失败提示和 provider 切换。参考：[MyMemory API spec](https://mymemory.translated.net/doc/spec.php)。
- Free Dictionary API 与 `dictionaryapi.dev` 都适合作为免费外部来源之一，但不应成为唯一可靠链路。参考：[FreeDictionaryAPI](https://freedictionaryapi.com/) 与 [Free Dictionary API](https://dictionaryapi.dev/)。

## 4. 用户视角问题与改进机会

### 4.1 “为什么这个词不见了？”

用户不会天然理解“弱正反馈”。从用户角度，它表现为昨天还标注的词今天不标了、只是没点却被系统当成认识、想继续提醒却找不到入口。

改进方向：

- 设置页用人话解释：多次看到但没有查，潜词会认为你可能认识它。
- 展示因弱反馈暂不标注的词数量和最近词表。
- 每个词提供“恢复提醒”“标为熟词”“总是提醒我”。
- tooltip 中提供“继续提醒”，避免用户必须进入设置页。
- 高级设置再暴露跳过次数、可见时长、半衰期和影响阈值。

### 4.2 “这个网页怎么用不了？”

用户不会区分 iframe、shadow DOM、SPA、富文本编辑器、CSS 污染或权限限制，只会感到没标注、很慢、页面乱了、输入受影响。

改进方向：

- popup 显示页面状态卡：当前模式、扫描时间、检查文本段、标注数量、风险提示。
- 页面不可读时仍提供重新扫描和复制最小诊断。
- 复杂页面自动建议仅手动查词或安全模式。
- 对编辑器、表单、代码区域、隐藏区域默认跳过。
- 为课程页、嵌入文章、文档预览建立单独兼容测试矩阵。

### 4.3 “查词失败后我该怎么办？”

联网失败如果只显示“失败”，用户无法判断是网络断了、服务挂了、限速、单词不存在，还是需要再点一次。

改进方向：

- tooltip 显示用户能懂的失败原因：网络异常、请求超时、服务不可用、请求过于频繁、未找到词条。
- popup 显示待重试数量，空队列显示暂无待处理。
- options 展示队列详情：单词、失败原因、尝试次数、下次重试时间。
- 单个 provider 失败后尝试备用 provider，仍失败才入队。
- 网络恢复或 alarm 触发后自动退避重试。

### 4.4 “它会不会偷发我看的内容？”

浏览器扩展天然敏感。用户需要知道本地保存了哪些词和偏好、什么时候联网、联网发送什么、如何导出、清空、关闭联网。

改进方向：

- 设置页增加“数据与隐私”中心。
- 明确承诺：默认只发送用户主动查的单词，不发送整页正文。
- 自定义 API token 遮罩显示，不写入日志，不随普通导出明文保存。
- 清空生词、熟词、弱反馈、在线缓存、重试队列、站点设置时分别说明影响范围。
- 复制诊断时不包含页面正文、完整 URL path、query、选中文本、cookie 或 token。

### 4.5 “我刚装上，第一分钟该做什么？”

新用户最怕“不知道潜词有没有在工作”。首次使用应像上手确认，不像设置说明。

改进方向：

- 安装后引导选择大致英语水平、标注密度和触发方式。
- 第一个英文页面打开 popup 时显示“已检查多少文本段、标注多少词”。
- 没有标注时显示最可能原因和一个推荐动作。
- 解释“我认识”“未查看”“继续提醒”会如何影响后续标注。
- 引导可跳过，也可在设置页重新打开。

### 4.6 “不同网站需求不一样”

看博客、技术文档、邮件编辑器、搜索结果、课程页时，用户对标注密度和自动插入的容忍度完全不同。

改进方向：

- 站点模式支持自动标注、仅手动查词、暂停、安全模式、低密度。
- 用户在某站点多次切换为仅手动时，提示是否记住。
- 当前站点使用自定义策略时，popup 明确显示。
- options 提供站点偏好列表和清空入口。
- 清空站点偏好不影响生词、熟词和联网缓存。

### 4.7 “我希望复盘，但不要变成背单词软件”

潜词的复盘应是阅读结束后的轻动作，不是打卡系统。

改进方向：

- 展示最近查过、查得最多、最近认识、今日新增。
- 高频查词提供一键标熟。
- 支持 CSV、JSON、Anki-friendly CSV 导出。
- 不做积分、排行榜、强提醒和系统通知。
- 复盘入口放在 popup 或 options，不主动打断阅读。

### 4.8 “我想相信它，但需要可撤销”

用户愿意接受智能判断的前提是能撤销。

改进方向：

- 刚点“我认识”后，tooltip 或 popup 提供短期撤销。
- 自动减少提醒要能看到原因并恢复单词。
- 自动切安全模式要能看到提示并手动恢复自动标注。
- 自动重试联网查词要能看到队列并清空。
- 破坏性清空操作必须二次确认。

### 4.9 “我不想理解一堆技术词”

潜词内部有 rank、弱反馈、扫描队列、provider、iframe、shadow DOM 等概念，但默认界面只应讲用户任务。

改进方向：

- “标注太多 / 太少”“查词失败”“当前站点不好用”“导出或清空数据”作为设置页首页入口。
- 技术详情放到高级设置和复制诊断。
- 把 `skipLimit` 翻译为“看到几次没查后减少提醒”。
- 把 provider 翻译为“词条来源”。
- 把扫描状态翻译为“本页已检查多少文本段”。

### 4.10 “我希望它尊重我正在做的事情”

同一个词在不同任务里的意义不同。阅读文章时标注是帮助，写作、搜索、填表、复制代码时可能是干扰。

改进方向：

- 正在输入时暂停自动标注，只保留手动查词。
- 阅读长文时优先标注正文和视口附近内容。
- 搜索结果页降低密度。
- 技术文档跳过代码块、命令、路径、类型名和变量名。
- 课程或文档预览页面支持 iframe，但给每个 frame 单独预算。

### 4.11 “我希望释义越来越适合我”

免费词典和机器翻译不可能总是命中阅读场景。用户需要能改、能记住、能优先显示。

改进方向：

- 用户可添加本地自定义释义。
- tooltip 折叠区提供“释义不准”。
- 自定义释义优先于联网结果。
- 词表标记本地词典、在线词典、机器翻译、缓存、用户自定义来源。
- 后续可按技术文档场景优先展示计算机相关释义。

### 4.12 “我希望反馈问题很轻松”

当页面不兼容、查词失败或标注异常时，用户最难的是描述问题。

改进方向：

- 提供一键复制脱敏诊断。
- 诊断包含扩展版本、浏览器类型、站点域名、站点模式、扫描统计、错误类型和重试队列数量。
- 剪贴板失败时显示只读文本框供手动复制。
- 提供“问题现象 / 期望结果 / 实际结果 / 诊断信息”反馈模板。
- 打开 issue 页面时只预填脱敏文本，并提醒不要粘贴隐私内容。

### 4.13 “我不想为了性能牺牲阅读节奏”

用户不会关心扫描算法，只会感到滚动、点击、选词、打开 tooltip 是否顺手。

改进方向：

- 用户交互优先级高于扫描。
- 重新扫描必须有 loading、禁用状态和失败提示。
- 长页面只先处理首屏和视口附近内容。
- 高频 mutation 页面自动降频，不持续占用主线程。
- 标注密度改变后不强行同步处理全页，而是预算内渐进刷新。

### 4.14 “我想把学习数据带走”

用户对生词、熟词、总是提醒和自定义释义有所有权。

改进方向：

- JSON 导出包含格式版本、导出时间、词条、来源、查看次数、最近查看时间。
- CSV 面向表格和笔记软件。
- Anki-friendly CSV 面向已有复习习惯用户。
- 导入时做 schema 版本校验和冲突提示。
- 导出前说明不包含整页浏览历史。

### 4.15 “我希望它在离线时也别装死”

联网能力失败不应影响本地标注和手动查词。

改进方向：

- 本地词典命中时显示“本地”。
- 网络不可用时保留本地释义、标注、手动查词。
- 联网失败说明不会影响本地能力。
- 待重试队列在网络恢复后再处理。
- 多次失败后显示“稍后自动重试”，而不是鼓励用户反复点击。

## 5. 优先级路线图

### P0：守住不卡顿和不破坏页面

#### 5.1 扫描性能预算

- 每片扫描目标控制在 8-12ms 内让出主线程。
- 首屏和视口附近优先，视口外延迟处理。
- 用户滚动、点击、选择文本、打开 tooltip 时暂停或降低扫描优先级。
- 高频 mutation 页面进入保守模式，合并重复扫描。
- 记录首轮扫描耗时、最大单片耗时、处理节点数、跳过节点数。

验收标准：

- 5000-10000 文本节点页面不出现明显卡顿。
- 重新扫描、密度调整、站点模式切换都有明确状态反馈。
- `dispose()` 后不再处理旧页面任务。

#### 5.2 复杂页面安全模式

- 默认不扫描输入框、编辑器、代码块、按钮、菜单、导航和隐藏区域。
- 检测富文本编辑器、邮件编辑区、代码编辑器时建议仅手动查词。
- 对广告 iframe、隐藏 iframe、极小 iframe 默认跳过。
- 对 mutation 过高区域设置冷却期。
- 安全模式仍保留选中文本手动查词。

验收标准：

- 复杂应用页面不因潜词造成输入异常、布局抖动或误操作。
- 用户能在 popup 内切换为仅手动查词或暂停当前站点。

#### 5.3 页面诊断与排错

当前已落地：

- popup 展示当前页面标注数、已检查文本段数、扫描状态和常见风险提示。
- 页面不可读时仍可重新扫描并复制最小诊断。
- 重新扫描有 loading、禁用、防重复点击、完成提示和失败提示。
- 站点模式切换有状态反馈，恢复自动标注会请求重扫。
- “少标一些”“多提醒一点”“恢复平衡”已接入密度快捷操作。
- 复制诊断失败时显示只读文本框。
- popup 已支持复制脱敏反馈模板，包含问题现象、期望结果、实际结果、隐私提醒和诊断信息，便于用户直接粘贴到 issue 或聊天反馈。

继续优化：

- 对页面不可读原因做更具体分类。
- 增加页面类型识别：文章页、搜索页、表单页、代码页、学习平台。
- 诊断中保留技术详情，但默认界面只显示用户能懂的原因。

### P1：把已有能力用户可见化

#### 5.4 弱正反馈透明化

- 设置页显示“因多次未查看而暂不标注”的词数量。
- 显示最近被跳过最多的 5-10 个词。
- 单词级提供恢复提醒、标为熟词、总是提醒。
- tooltip 增加“继续提醒”。
- 高级设置暴露跳过次数、可见时长、半衰期和影响阈值。

验收标准：

- 用户 10 秒内能找到“为什么某个词不再标注”的解释和恢复入口。
- 用户无需理解 `skipCount`、`decayHalfLifeDays` 等内部字段。

#### 5.5 联网重试队列可见化

- popup 显示轻量摘要：`联网重试：3 个待处理`。
- options 新增“联网重试队列”面板。
- 队列项显示单词、失败原因、尝试次数、下次重试时间。
- 提供清空重试队列，确认文案说明不会删除生词。
- 达到最大尝试次数后停止重试并展示最终原因。

验收标准：

- 用户知道失败请求没有丢。
- 用户能清理队列，避免自动重试不透明。

#### 5.6 数据与隐私中心

- 展示本地保存的数据类型。
- 展示哪些动作会联网，以及联网发送哪些字段。
- 支持清空生词、熟词、弱反馈、在线缓存、重试队列、站点设置。
- 支持导出全部数据。
- 支持关闭联网补查。
- 自定义 endpoint token 不明文展示、不写日志、不随普通导出明文保存。

验收标准：

- 用户知道数据边界。
- 清理操作均有确认提示和影响说明。

#### 5.7 用户任务型设置首页

- 首页按用户问题组织：标注太多或太少、某词不想再标、某词想继续提醒、查词失败、导出或清空数据、当前站点不好用。
- 高级参数折叠到“高级设置”。
- 每个任务入口都给一句人话解释和一个主操作。

验收标准：

- 普通用户不需要理解内部数据结构也能找到入口。
- 高级用户仍能调整细节。

### P1：联网补查可靠性增强

#### 5.8 Provider 链与归因

建议 provider 顺序：

1. 本地词典与在线缓存。
2. FreeDictionaryAPI。
3. `dictionaryapi.dev`。
4. MyMemory 翻译英文释义。
5. 用户自定义端点。

每个 provider 统一返回：

- 成功词条。
- 错误类型。
- 来源标识。
- `retryAfter` 或熔断时间。
- 是否允许入队重试。

当前已落地：

- `freedictionaryapi.com` 失败或缺词时会尝试 `dictionaryapi.dev`。
- 主 provider `fetch` 抛网络错误时也会尝试 `dictionaryapi.dev`，备用成功则直接返回词条。
- `dictionaryapi.dev` 返回英文释义后会继续用 MyMemory 翻译中文。
- attribution 会标记最终词典服务来源。
- tooltip 会同时展示词典来源和中文翻译来源，例如 `dictionaryapi.dev` 与 `中文：MyMemory`，避免把机器翻译伪装成本地释义。
- tooltip 会根据联网补查结果展示更具体的失败提示；请求已入队时会提示“已加入重试队列，稍后自动重试”，避免用户反复点击。
- 备用 provider 失败时保留主 provider 原始错误分类。

继续优化：

- 在线缓存命中时展示“缓存结果”。
- provider 失败日志不能记录敏感 header 或 token。

#### 5.9 熔断、退避和重试

- 429、5xx、timeout 后进入 provider 级冷却期。
- 对同一单词重复点击合并请求，不并发打同一 provider。
- 重试使用指数退避和最大尝试次数。
- service worker 启动时补建关键 alarm。
- 网络恢复后处理到期队列，但仍遵守 provider 熔断。

验收标准：

- 单个 provider 失败不影响后续 provider。
- 失败不会导致 tooltip 悬挂或无限重试。
- 限流时不会被立即重复打爆。

#### 5.10 用户自定义端点

- 作为高级设置提供 URL、方法、字段映射和测试连接按钮。
- 默认只允许 HTTPS 或 localhost。
- 可选 token 输入后遮罩显示。
- 只发送用户请求的单词，不发送整页文本。
- 不在日志、诊断、普通导出中记录 token、完整 headers 或完整响应。

验收标准：

- 技术用户可接入自己的词典服务。
- 普通用户默认不需要配置。

### P1：页面兼容性增强

#### 5.11 iframe 策略

- 保留普通 iframe 支持。
- 评估是否开启 `match_about_blank`，只针对确有需求的场景。
- 对 `data:`、`blob:` frame 是否使用 `match_origin_as_fallback` 单独评估。
- 每个 iframe 设置独立扫描预算。
- 隐藏、极小、广告 iframe 默认跳过。

验收标准：

- 课程页面、嵌入文章、文档预览可用性提升。
- 广告和隐藏 iframe 不造成性能负担。

#### 5.12 Shadow DOM 与 Web Components

- open shadow root 可扫描和监听。
- closed shadow root 不强行处理，只保留手动查词。
- tooltip 自身继续用 Shadow DOM 隔离，不污染页面。
- 增加 Web Components smoke case。

验收标准：

- Web Components 正文覆盖更多。
- 不尝试绕过 closed shadow root。

#### 5.13 文本与区域过滤

- 跳过代码块、命令行、URL、文件路径、camelCase、全大写缩写和变量名。
- 对专有名词、人名、品牌名降低标注。
- 对中文段落中的少量英文降低密度。
- 支持复数、过去式、进行时、比较级等词形还原。
- 探索常见短语识别，但不让 tooltip 变重。

验收标准：

- 技术文档误标明显减少。
- 手动查词仍能覆盖自动策略漏掉的词。

### P2：交互体验增强

#### 5.14 首次使用与状态感

当前已落地：

- 设置页顶部显示“三步开始使用潜词”轻量引导。
- 支持“安静阅读 / 平衡默认 / 多提醒学习”预设。
- 用户可跳过并重新打开引导。
- popup 在页面不可读、仅手动、暂停站点、已扫描但 0 文本段等空状态中提供下一步动作，例如重新扫描、切回自动标注、手动查词或复制反馈模板。
- popup 按钮具备统一 `focus-visible` 焦点环和至少 32px 的操作命中高度，键盘用户更容易看见当前位置。
- popup 的快捷密度调整支持撤销最近一次操作；撤销会恢复调整前密度并重新扫描当前页，且保存未完成时会进入 busy 状态防重复点击，并暂时禁用重新扫描，降低误点和并发刷新成本。

继续优化：

- popup 优先显示当前页面状态卡。
- 0 标注时给出最可能原因和一个推荐动作。
- 安装后第一个英文页面给出最轻量的“潜词正在工作”证据。

#### 5.15 标注密度与阅读模式

当前已落地：

- `UserProfile.annotationDensity` 使用 `0.75` 到 `1.25` 的连续密度值。
- 设置页以滑块展示，文案为“想少打扰就往左，想多提醒就往右”。
- 决策层用 `threshold / annotationDensity` 调整自动标注阈值。

继续优化：

- popup 提供“阅读模式”和“专注模式”。
- 站点级密度偏好可记忆、可清空。
- 页面类型自动影响密度，但必须可覆盖。

#### 5.16 tooltip 小而有用

当前已落地：

- tooltip 支持 `Escape`、显式关闭、外部点击关闭、键盘聚焦和焦点返回。
- 加载态可关闭，用户关闭后迟到联网结果不会重新弹出。
- 动态联网状态使用温和状态播报。
- 按钮具备明确 `aria-label`、可见焦点和至少 32px 的操作命中区；动作区有最大宽度和换行保护，减少触控困难时仍避免挤坏 220px 卡片。

继续优化：

- 默认卡片只展示单词、音标、中文释义、主操作。
- 折叠区展示例句、词性、来源、继续提醒、释义反馈。
- 对“我认识”“继续提醒”“释义不准”提供短期撤销。

#### 5.17 学习回顾与导出

当前已落地：

- 设置页已有“最近查过 / 查得最多 / 最近认识”任务卡片。
- “查得最多”支持标为认识。
- 完整生词表支持 CSV 与 JSON 导出。

继续优化：

- 增加今日新增、今日反复查词、可能可以标熟。
- 支持 Anki-friendly CSV。
- JSON 导出包含 format 版本、导出时间、词条来源和查看统计。
- 后续支持 JSON 导入、schema 校验和冲突提示。

#### 5.18 释义质量与个性化

- tooltip 折叠区提供“释义不准”。
- 支持用户自定义本地释义。
- 自定义释义优先于在线 provider。
- provider 返回冲突时优先展示用户确认过的释义。
- 词表显示哪些词使用了自定义释义。

验收标准：

- 用户能修正影响自己的错误释义。
- 机器翻译结果不伪装成本地词典。

#### 5.19 无障碍与低打扰

- 鼠标、键盘、触控都能使用核心功能。
- 按钮目标尺寸和焦点可见性满足可用性要求。
- 深色页面、高对比模式下 tooltip 可读。
- 默认不使用浏览器系统通知。
- 错误提示按 tooltip、popup、options 分层承载。

验收标准：

- 不打断阅读。
- 不牺牲键盘用户和低视力用户体验。

### P3：探索项

#### 5.20 PDF、字幕与课程页

- 浏览器原生 PDF viewer 可能受注入限制，应先做能力探测。
- 课程页面常见跨域 iframe，应优先保证手动查词和诊断提示。
- 视频字幕只考虑页面 DOM 中可见字幕，不做音视频识别。
- 不承诺绕过浏览器和站点安全边界。

#### 5.21 跨设备与备份

- 优先完善 JSON 导出和导入。
- 后续再评估 `storage.sync`，明确同步容量和隐私边界。
- 自定义 API token 不随普通导出明文保存。
- 导入时做 schema 版本校验和冲突提示。

#### 5.22 自适应站点建议

- 某站点多次切为仅手动查词，提示是否记住。
- 某站点扫描总是高频 mutation，建议安全模式。
- 某站点几乎没有英文正文，降低自动扫描频率。
- 所有建议必须可拒绝、可撤销、可清空。

## 6. 数据模型建议

### 6.1 弱反馈

```ts
interface FeedbackSettings {
  skipLimit: number;
  skipDelayMs: number;
  decayHalfLifeDays: number;
  suppressionMode: 'conservative' | 'balanced' | 'aggressive';
}
```

```ts
interface WordPreference {
  word: string;
  remindAlways?: boolean;
  suppressOnCurrentSite?: boolean;
  customTranslation?: string;
  updatedAt: number;
}
```

### 6.2 站点策略

```ts
interface SitePolicy {
  hostname: string;
  mode: 'auto' | 'manual-only' | 'paused' | 'low-density' | 'safe';
  updatedAt: number;
}
```

清空站点设置只恢复各网站默认自动模式，不删除生词、熟词、弱反馈或联网缓存。

### 6.3 联网 provider

```ts
interface OnlineDictionaryProviderResult {
  entry?: OnlineDictionaryEntry;
  errorKind?: 'not_found' | 'rate_limited' | 'service_unavailable' | 'network_error' | 'timeout' | 'parse_error';
  providerId: string;
  serviceLabel: string;
  serviceUrl?: string;
  retryAfterMs?: number;
  allowQueueRetry: boolean;
}
```

### 6.4 联网重试队列

```ts
interface OnlineLookupQueueItem {
  word: string;
  attempts: number;
  lastErrorKind: 'rate_limited' | 'service_unavailable' | 'network_error' | 'timeout' | 'parse_error';
  lastTriedAt: number;
  nextRetryAt: number;
}
```

### 6.5 页面诊断

```ts
interface PageDiagnostics {
  siteMode: SitePolicy['mode'];
  scannedTextNodes: number;
  annotatedWords: number;
  skippedRegions: number;
  lastScanDurationMs: number;
  warnings: Array<'dynamic-page' | 'editor-detected' | 'iframe-limited' | 'permission-limited' | 'code-heavy'>;
}
```

诊断报告可包含站点域名和统计信息，不包含页面正文、完整 URL path、query、选中文本、cookie 或 token。

## 8. 验收指标

### 8.1 用户体验指标

- 新用户 3 步内完成初始配置。
- 用户 10 秒内找到“为什么某个词不再标注”的解释和恢复入口。
- 联网失败后能看到明确原因和待重试状态。
- 问题站点能在 popup 内切换为仅手动查词或暂停。
- 没有标注时，用户能看到最可能原因和推荐动作。

### 8.2 性能指标

- 首屏扫描不出现用户可感知卡顿。
- 单片扫描尽量控制在 8-12ms。
- 长页面 smoke 不触发明显长任务。
- 高频 mutation 页面不会持续占用主线程。
- 用户交互优先于扫描和重扫。

### 8.3 可靠性指标

- 第三方 API 失败不会导致查词流程悬挂。
- 429、5xx、timeout 有退避，不无限重试。
- alarm 丢失后 service worker 启动可补建。
- 队列达到最大尝试次数后停止并展示原因。
- 本地查词能力不受联网失败影响。

### 8.4 隐私指标

- 默认只在用户主动联网查词时发送单词。
- 不发送整页内容。
- 不记录 token 和敏感 header。
- 用户可导出和清空本地数据。
- 复制诊断和反馈模板默认脱敏。

## 9. 用户旅程验收剧本

### 9.1 新用户第一次打开英文网页

目标体验：

- 用户打开 popup，能看到潜词是否已在当前页工作。
- 如果没有标注，能看到最可能原因。
- 用户能一键调整为少标、平衡或多标。
- 用户不用阅读 README 就知道 `Alt + 选词` 可以手动查词。

失败信号：

- 用户看不到任何状态，只能猜扩展是否坏了。
- 设置项出现大量内部术语。

### 9.2 阅读过程中标注太多

目标体验：

- 用户能在 popup 或设置页快速降低密度。
- 用户能对单个词点“我认识”或“以后少标”。
- 页面不会因为重新扫描卡顿。

失败信号：

- 用户只能全局关闭扩展。
- 降低密度后不知道是否生效。

### 9.3 某个词突然不再标注

目标体验：

- 用户能在设置页看到它是否因弱反馈被隐藏。
- 用户能恢复提醒或设为总是提醒。
- 界面用“多次看到但没查，潜词猜你可能认识”解释原因。

失败信号：

- 用户必须理解 `skipCount` 或 `decayHalfLifeDays` 才能排查。
- 只能重置全部反馈，不能修复单词级误判。

### 9.4 联网查词失败

目标体验：

- tooltip 告诉用户是网络异常、超时、服务不可用、限流还是未找到词条。
- popup 显示待重试数量。
- 设置页能查看队列、清空队列、知道下次重试时间。
- 本地查词能力不受影响。

失败信号：

- 只显示“失败”。
- 用户不知道是否需要重复点击。

### 9.5 复杂页面不好用

目标体验：

- popup 诊断提示页面可能是编辑器、代码页、动态页面或权限限制。
- 用户能一键重新扫描、切到仅手动查词或暂停站点。
- 用户能复制脱敏诊断反馈问题。

失败信号：

- 页面错乱或输入受影响。
- 用户只能卸载扩展来恢复页面。

### 9.6 阅读结束后轻复盘

目标体验：

- 用户能看到最近查过、查得最多和今日新增。
- 用户能一键标熟已经掌握的词。
- 用户能导出今日或全部生词。

失败信号：

- 生词列表只是原始表格。
- 复盘体验过重，像被迫进入背词软件。

## 10. 风险与取舍

- **功能增多会损害轻量感**：tooltip 默认保持小，复杂功能放到折叠区、popup 摘要和 options。
- **iframe 覆盖会增加性能成本**：按 frame 大小、可见性和页面类型做预算，不追求全量扫描。
- **自定义端点增加安全复杂度**：必须作为高级设置，默认不启用。
- **弱反馈过度智能会降低信任**：任何自动判断都要能解释、撤销、关闭。
- **复习功能容易跑偏**：只做阅读后的轻复盘，不做完整背词流程。
- **自动页面类型识别可能误判**：所有建议必须可覆盖、可拒绝、可清空。

## 11. 推荐下一步

建议马上进入“已有能力用户可见化”：

1. 在 popup 显示联网重试队列摘要。
2. 在 options 增加“联网重试队列”面板，支持查看和清空。
3. 在 options 的“标注策略”补充弱反馈隐藏词明细和单词级恢复。
4. 在 tooltip 增加“继续提醒”。
5. 为上述功能补单元测试。
6. 跑 `npm run typecheck`、相关 `vitest` 和 `npm test`。

这条路径能最快把已有技术能力变成用户能理解的体验，不继续堆用户看不见的基础设施。
