日期：2026-07-10

范围：各环节用户操作体验（不扩权限、不做背词平台、不重写架构）

---

## 1. 体验原则（所有改动的过滤器）

潜词的品牌承诺是：**安静、克制、可解释、可撤销**。

| 原则 | 含义 | 反例（避免） |
| --- | --- | --- |
| **3 秒看懂** | 打开 popup / 设置页，先看到「它在干什么」 | 先看到一堆高级选项 |
| **主路径最短** | 认识 / 查词 / 少标一点 步数最少 | 为修一个词要进三层面板 |
| **技术藏后** | CSS 选择器、iframe、provider 不挡主路径 | popup 中部大段「排除选择器」 |
| **一次一事** | 一个界面区块只服务一个用户任务 | 诊断区同时塞密度、反馈、导出 |
| **可撤销** | 自动判断都能恢复 | 只有「重置全部」没有单词级恢复 |
| **少字面技术词** | 用用户任务语言 | 「同源 iframe」「弱反馈 skipLimit」 |

## 2. 当前界面地图（现状快照）

```text
阅读页
  ├─ 虚线标注词
  ├─ 悬停/点击 → 释义卡（认识 / 继续提醒 / 关闭 / 释义不准 / 来源）
  ├─ Alt+选词 / 右键 → 手动查词
  └─ 缺词 → 联网查询 / 已关闭联网提示

扩展弹窗 popup（约 280px 宽，纵向很长）
  1. 标题「潜词 / 当前站点」
  2. 域名
  3. 快速查词
  4. 五种站点模式（自动/低密度/安全/仅手动/暂停）  ← 占位多
  5. 当前站点高级（排除选择器 + iframe）           ← 技术向
  6. 页面诊断（状态、建议按钮、重扫、复制）
  7. 联网重试摘要
  8. 打开完整设置

设置页 options（单页长滚动）
  引导 → 学习回顾 → 词表检索 → 自定义释义
  → 水位线 → 密度 → 离线词库 → 标注策略
  → 触发方式 → 划线颜色 → 快捷键
  → 生词/熟词表 → 重试队列 → 数据与隐私
```

**总体判断**：功能已经够用甚至偏多；主要问题不是「缺能力」，而是 **信息架构变重、主路径被高级选项挤占、部分文案仍偏工程化**。

## 3. 分环节体验分析

### 3.1 首次安装 / 第一次打开英文页

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 引导 | 设置页有三步引导 + 预设 | 用户先点图标看到的是 **popup**，不是设置引导 |
| 工作证据 | popup 有标注数/检查段数 | 第一次 0 标注时原因文案偏长，动作按钮仍偏分散 |
| 默认可用 | 默认自动标注 | 好；但用户不知道「现在该干什么」 |

**用户真实问题**

1. 装完了，有没有在工作？  
2. 没有标注是坏了还是我词汇够？  
3. 我想少标一点，点哪里？

**目标体验**

- 安装后第一次打开 popup：顶部就是 **状态卡**「正在本页工作 / 已检查 N 段 / 标注 M 词」。  
- 0 标注时：一句原因 + **一个主按钮**（重新扫描 / 多提醒一点 / 打开引导）。  
- 引导可从 popup 一键「去设置看三步说明」，不必自己找。

---

### 3.2 阅读中：标注与释义卡

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 触发 | 悬停或点击可配 | 默认悬停易「路过就弹」；有人嫌吵但不知可改点击 |
| 卡片内容 | 词 / 音标 / 中文 / 认识 / 继续提醒 / 来源 / 释义不准 | 按钮横排在 220px 卡片上仍偏挤 |
| 悬停稳定性 | 已加长延迟与悬停保活 | 仍可能被页面 fixed 层/滚动打断（边缘） |
| 认识后 | 有撤销条 | 好 |
| 释义不准 | 写入自定义词库 + 提示去设置改 | **无法在卡片内直接改释义**，闭环断裂感仍在 |

**用户真实问题**

1. 卡片一晃就没了（已改善，需回归）。  
2. 我想改错的中文释义，为什么要去设置页？  
3. 「继续提醒」和「认识」哪个先点？  
4. 来源链接一堆，会不会太吵？

**目标体验**

- 默认卡片：`单词 · 音标 · 中文 · 认识 · 关闭`。  
- 次要操作折叠：继续提醒 / 释义不准 / 来源详情。  
- 「释义不准」展开 **一行输入 + 保存**（写自定义词库），不必跳设置。  
- 悬停模式保留；设置里用「路过就弹？改成点击」人话说明。

---

### 3.3 漏词：手动查词

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| Alt+选词 | 有，快捷键可配 | 新用户不知道；popup 未强调 |
| 右键菜单 | 有「翻译所选单词」 | 与产品名「潜词」不一致，但可用 |
| 弹窗快速查词 | 有 | 与页面查词结果展示不一致（无音标来源层级） |

**目标体验**

- popup 空状态 / 诊断区固定一行：**「漏了？Alt+选中单词」**（随用户快捷键变化）。  
- 快速查词结果与释义卡语义对齐：认识 / 来源一句人话。  
- 右键文案可改为「用潜词查词」（小改）。

---

### 3.4 标太多 / 标太少

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 密度滑块 | 设置页有 | 日常调节路径偏长 |
| popup 快捷 | 少标一些 / 多提醒 / 恢复平衡 | 只在特定诊断条件下出现，用户找不到时会懵 |
| 站点模式 | 5 个并列按钮 | **认知负担高**：低密度 vs 少标一些 vs 安全模式 难分清 |
| 单词级 | 认识 / 弱反馈恢复 / 总是提醒 | 设置里有，阅读中够用但命名偏内行 |

**概念冲突（重点）**

当前同时存在：

- 标注密度（全局）  
- 低密度站点模式  
- 安全模式（跳过区域）  
- 仅手动  
- 弱反馈隐藏  

用户会问：「我到底该调哪个？」

**目标体验（建议统一心智）**

用用户任务映射，而不是技术旋钮：

| 用户说 | 推荐入口 | 背后实际动作 |
| --- | --- | --- |
| 这个站标太多了 | popup 主操作「本站少标一点」 | 优先调站点 low-density 或全局密度一步 |
| 这个站很乱/会误伤 | 「本站更稳一点」 | safe 或仅手动 |
| 这个站先别动 | 「暂停本站」 | paused |
| 这个词我会了 | 卡片「认识」 | known |
| 这个词别消失 | 卡片「继续提醒」 | alwaysAnnotate |

**建议**：popup **不要默认摊开 5 个模式**；改为：

1. 当前状态一行：`本站：自动标注 · 已标 12 词`  
2. 三个主按钮：`少标一点` / `更稳一点` / `暂停`  
3. 「更多站点选项」折叠：完整五模式 + 排除选择器 + iframe  

---

### 3.5 页面不好用 / 诊断与反馈

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 诊断文案 | 已较完整 | 段落长，多条警告并列 |
| 按钮 | 重扫、复制诊断、复制反馈、密度、仅手动 | 主次不清 |
| 高级 | 排除选择器 textarea | 普通用户看不懂，且占主视区 |

**目标体验**

诊断区结构固定为：

```text
[状态] 本页已检查 42 段，标注 8 词 · 空闲
[原因] 一句人话（若有问题）
[主按钮] 重新扫描本页
[次按钮] 本站更稳一点 · 复制反馈
[折叠] 技术详情 / 高级站点设置
```

### 3.6 设置页信息架构

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 布局 | 单页从上到下全部堆叠 | 像控制台，不像「任务入口」 |
| 检索 | 顶部有词表检索 | 好，但位置与自定义释义、生词表关系弱 |
| 自定义释义 | 独立面板 | 与「释义不准」联动仍弱（要跳页找词） |
| 导出 | 生词 CSV/JSON/Anki + 完整备份 | 入口分散（词表 vs 隐私） |

**目标体验：按用户任务分组（Tab 或锚点导航）**

建议 4 组（不必真做复杂 SPA，可用顶栏锚点）：

1. **开始与阅读**  
   引导、水平、密度、触发方式、颜色、快捷键、离线词库  
2. **我的词**  
   检索、学习回顾、生词、熟词、自定义释义  
3. **标注策略**  
   弱反馈、恢复提醒、总是提醒  
4. **数据与隐私**  
   联网开关、重试队列、缓存、站点设置、导入导出  

首页只显示：「你可能想…」四个大入口卡片。

### 3.7 联网查词与失败

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 成功 | 有来源归因 | 来源链接偏多 |
| 失败 | 分类错误 + 入队 | 卡片上「已加入重试队列」后用户不知去哪看 |
| 关闭联网 | 设置有开关 | popup 快速查词失败时未引导「是否关闭了联网」路径不够显眼 |

**目标体验**

- 失败：`查不到 · 已安排稍后重试` + 链接「查看待重试」打开设置锚点。  
- 关闭联网时：缺词卡只说「仅本地模式」，并给「去开启联网」次要入口。

---

### 3.8 数据、备份与隐私

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 清空 | 有确认 | 好 |
| 导入 | confirm 文案较长 | 可接受；可再拆「预览将导入什么」 |
| 导出 | 多种格式 | 用户不知该导「生词 JSON」还是「完整备份」 |

**目标体验**

隐私面板用表格说清：

| 我想… | 点这个 |
| --- | --- |
| 换电脑把学习记录带走 | 导出完整备份 |
| 只要生词表给 Anki | 生词区 Anki |
| 清空误缓存 | 清空联网缓存（不影响自定义/生词） |

---

### 3.9 键盘 / 触控 / 无障碍

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 标注词键盘 | Tab / Enter 可用 | 好 |
| 卡片 | Escape、焦点返回 | 好 |
| popup | 按钮有 focus-visible | 五模式列表键盘路径很长 |
| 触控 | 32px 命中 | 悬停触发在触控设备不适用 → 应用点击 |

**目标体验**

- 触控/无 hover 能力时自动倾向点击触发（或首次提示）。  
- popup 折叠高级区后，键盘 tab 次数明显下降。

## 5. 目标信息架构（确认后实施）

### 5.1 Popup 重构（核心）

```text
┌─────────────────────────────┐
│ 潜词 · example.com          │
│ [状态卡] 已检查 42 段 · 标 8 │
│ 一句提示（可选）             │
├─────────────────────────────┤
│ 本站现在：自动标注           │
│ [少标一点] [更稳一点] [暂停] │
│ ▸ 更多站点选项               │  ← 折叠：五模式/排除/iframe
├─────────────────────────────┤
│ 快速查词  [_______] [查]    │
│ 结果…  [标为认识]            │
├─────────────────────────────┤
│ 本页工具                     │
│ [重新扫描]  [复制反馈]       │
│ ▸ 诊断详情                   │  ← 折叠技术数字
├─────────────────────────────┤
│ 联网重试：2  ·  打开设置     │
└─────────────────────────────┘
```

**映射规则（建议写死产品文案）**

| 按钮 | 行为 |
| --- | --- |
| 少标一点 | 若已是 auto → 切 low-density；若已 low-density → 再降全局密度一步或提示已最低 |
| 更稳一点 | auto/low-density → safe；已在复杂页 → 可二次确认「仅手动」 |
| 暂停 | paused |
| 恢复 | 从 paused/manual/safe/low-density 回 auto（状态卡主按钮） |

> 具体映射可在确认阶段微调；原则是 **用户不需要理解五个枚举名**。

### 5.2 释义卡重构

```text
┌──────────────────────┐
│ word          [×]    │
│ /phonetic/           │
│ 中文释义……           │
│ [认识]  [⋯更多]      │  ← 更多：继续提醒、改释义、来源
└──────────────────────┘
```

「改释义」内联：

```text
│ 释义不准？            │
│ [输入框____________]  │
│ [保存为自定义] [取消] │
```

### 5.3 设置页分组

顶栏或侧栏（轻量）：

`阅读设置 | 我的词 | 标注策略 | 数据隐私`

默认打开「我的词」或记住上次分组。

## 6. 实施阶段（确认后按序做）

### 阶段 UX-0：文案与概念对齐（纯文案/小改，风险最低）

- 统一用户语言：少标一点 / 更稳一点 / 暂停本站  
- 诊断与空状态压到「一句原因 + 一主按钮」  
- 右键菜单改为「用潜词查词」  
- README 使用说明与界面同步  

**Done-means**

- 不改变数据结构  
- 相关 popup/options 文案单测快照或包含断言更新  
- `npm run typecheck` + 相关 vitest  

### 阶段 UX-1：Popup 信息架构（最大体验收益）

- 状态卡置顶  
- 三主按钮 + 折叠「更多站点选项」  
- 诊断详情折叠  
- 漏词提示固定露出  

**Done-means**

- popup 默认首屏（约 280×500 可视）无需滚动即可完成：看状态、少标、重扫、查词  
- 高级排除选择器默认不可见  
- `tests/unit/popup.test.ts` 更新并通过  

### 阶段 UX-2：释义卡轻量与就地改释义

- 次要操作进「更多」  
- 释义不准 → 内联编辑自定义释义并立即生效  
- 来源默认收起到更多  

**Done-means**

- 自定义释义保存后同词再次打开卡片立即显示新释义  
- tooltip 相关单测通过  

### 阶段 UX-3：设置页任务导航

- 顶栏四分组（或锚点）  
- 自定义释义与「释义不准」词自动高亮/滚入  
- 导出说明表：完整备份 vs 生词表  

**Done-means**

- 从任意分组可 1 次点击到「我的词 / 隐私」  
- options 相关单测通过  

### 阶段 UX-4：触控与细节抛光

- 粗指针/触控偏好点击触发（或提示）  
- 导入预览「将写入：生词 N · 自定义 M · 站点 K」  
- 动画与间距微调用（保持克制）  

**Done-means**

- 有明确测试或手动验收清单  
- 不引入重型 UI 库

## 7. 非目标（本体验规划不做）

- 不做账号、云同步 UI、打卡、排行榜  
- 不把 tooltip 做成词典百科页  
- 不默认打开系统通知  
- 不为「好看」引入 React/组件库（保持现有 vanilla + 轻 CSS）  
- 不在本阶段继续堆兼容选择器矩阵

## 8. 验收剧本（用户走查）

### 剧本 A：新用户 1 分钟

1. 安装扩展，打开英文文章  
2. 点图标 → 立刻知道是否在工作  
3. 若无标注，能一键重扫或多提醒  
4. 不必进入设置也能开始用  

### 剧本 B：标太多

1. popup 一键「少标一点」  
2. 页面刷新感可接受  
3. 单个词仍可用「认识」处理  

### 剧本 C：释义不对

1. 打开卡片 → 释义不准 → 就地改 → 保存  
2. 再悬停同一词，已是新释义  

### 剧本 D：页面捣乱

1. 诊断提示可理解  
2. 「更稳一点」后页面不乱  
3. 高级选择器在折叠里，不强迫普通用户  

### 剧本 E：换机

1. 设置 → 导出完整备份  
2. 新环境导入 → 生词与自定义仍在
