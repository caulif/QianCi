## 1. 产品承诺（体验评价标尺）

潜词承诺：**安静、克制、可解释、可撤销**。

| 标尺 | 通过标准 | 当前大致水平 |
| --- | --- | --- |
| 3 秒看懂 | 打开 popup 立刻知道「在不在工作 / 标了多少」 | **已改善**（状态卡置顶） |
| 主路径最短 | 认识 / 少标 / 漏词 1～2 步 | **主体达标**，个别闭环仍绕 |
| 技术藏后 | CSS、iframe、模式枚举不挡主路径 | **已改善**（折叠高级区） |
| 一次一事 | 一个区块只服务一个用户任务 | **部分仍重叠**（见 §5） |
| 可撤销 | 自动判断有恢复入口 | **单词级较好**；站点级/弱反馈级仍可加强 |
| 少技术词 | 用户任务语言 | **主路径较好**；策略区/README 仍有残留 |

## 2. 改造后界面地图（现状快照）

```text
阅读页 (content)
  ├─ 虚线标注词
  ├─ 悬停 / 点击 → 释义卡
  │     主操作：认识 · 更多 · 关闭
  │     更多：继续提醒 · 改释义 · 来源
  ├─ 认识后：撤销条
  ├─ 继续提醒后：确认条 + 撤销
  ├─ 缺词：联网查询 / 仅本地提示
  ├─ Alt|Ctrl|Shift + 选词 → 手动查词
  └─ 右键「用潜词查词」

扩展弹窗 popup（约 280px）
  1. 状态卡：站点 · 段数/词数 · 提示 · 漏词捷径 ·（非 auto 时）恢复自动
  2. 本站控制：少标一点 / 更稳一点 / 暂停 + 折叠「更多站点选项」
  3. 快速查词 + 标为认识
  4. 本页工具：重扫 / 复制反馈 + 条件密度按钮 + 折叠诊断
  5. 底部：联网重试摘要 · 打开设置

设置页 options（单页 + 顶栏四锚点）
  阅读设置 │ 我的词 │ 标注策略 │ 数据与隐私
  ├─ 引导 / 水位线 / 密度 / 词库包 / 触发 / 颜色 / 快捷键
  ├─ 学习回顾 / 检索 / 自定义释义 / 生词熟词导出
  ├─ 弱反馈节奏 / 被跳过的词 / 总是提醒
  └─ 联网开关 / 重试队列 / 备份导入导出 / 清空
```

**总体判断（改造后）**：

- 功能面已经偏完整，甚至略超「极简查词」的日常需要。  
- 上一轮 IA 折叠显著减轻了 popup 首屏压力。  
- **剩余问题集中在：多旋钮概念仍并存、反馈闭环半透明、跨界面跳转无锚点、触控/悬停未自适应、文案与 README 不同步、部分状态机边界不直观。**

## 3. 端到端交互链路

### 3.1 主阅读闭环

```text
扫描正文 → shouldAnnotateWord → 插入标注
  → 用户悬停/点击
  → resolveEntry（自定义 > 联网缓存 > 离线包）
  → 释义卡
  → [认识] → 写 known + 去标注 + 撤销条
  → [继续提醒] → alwaysAnnotate + 清 skip
  → [改释义] → 自定义词库立即生效
  → 路过未点开 → 弱反馈 skip 计数（不可见）→ 达阈值后不再标注
```

### 3.2 漏词闭环

```text
页面未标出
  → Alt+选词 / 右键 / popup 快速查词
  → 有词条：展示 +（popup）可标认识
  → 无词条：联网 → 成功缓存 / 失败入队
```

### 3.3 站点干扰闭环

```text
标太多 / 页面乱
  → popup「少标一点」→ low-density 或再降全局密度
  → popup「更稳一点」→ safe → 再点 → manual-only
  → popup「暂停」→ paused（连手动也不响应）
  → 「恢复自动」→ auto + 重扫
```

### 3.4 设置与数据闭环

```text
引导预设 → 密度 + 触发方式
词表检索 → 生词/熟词操作 → CSV/JSON/Anki
隐私 → 完整备份 / 导入冲突策略 / 清空缓存与站点
```

## 4. 分场景体验分析（基于当前代码）

### 4.1 首次安装 / 第一次打开英文页

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 工作证据 | popup 顶部状态卡 | 好 |
| 引导 | 仅在 options，需「打开设置」 | **安装后用户未必会进设置**；popup 无「三步说明 / 预设」入口 |
| 0 标注 | 一句原因 + 漏词提示 | 好；「多提醒一点」仅在极窄条件下出现（auto、0 词、0 警告、有扫描段） |
| 默认触发 | hover | 新用户易感觉「路过就弹」却不知道可改点击 |

**用户真实问题**

1. 装完了，该不该进设置？  
2. 为什么一扫就有/没有标注？和「四级」水位线有什么关系？  
3. 悬停太吵怎么办？（答案藏在设置「触发方式」）

**可优化方向**

- popup 首次（`onboardingDismissedAt` 未设）显示轻量一行：`第一次用？选安静阅读 / 打开说明`。  
- 状态卡在 0 标注时固定露出「多提醒一点」或「打开引导」，不必依赖过严的诊断条件。  
- 粗指针设备提示「建议点击查词」（UX-4 未做）。

---

### 4.2 阅读中：标注与释义卡

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 主操作 | 认识 / 更多 / 关闭 | 主路径清晰 |
| 次要 | 继续提醒、改释义、来源在「更多」 | 好；「改释义」发现性依赖多点一次 |
| 悬停保活 | 420ms + 卡片 hover + 焦点保活 | 明显改善；fixed 遮挡避让已有 |
| 展开更多后高度 | 放置仍按 `TOOLTIP_HEIGHT = 108` 估算 | **展开「更多」或改释义表单后可能被视口裁切**，未按实际高度重算 placement |
| 认识 | 立即去标注 + 撤销 | 好 |
| 继续提醒 | 确认条；词本身未必立刻「更显眼」 | 用户可能以为没生效（只有文案确认） |
| 弱反馈 | 背景自动累计 | **阅读中完全无感知**；词「突然不再出现」时用户归因困难 |

**用户真实问题**

1. 这个词昨天还在，今天怎么没了？（弱反馈 / 密度 / 水位线 三者都可能）  
2. 「继续提醒」和设置里的「总是提醒」是不是一回事？（是同一机制，命名两套）  
3. 卡片展开后被顶栏挡住怎么办？

**可优化方向**

- 展开更多 / 打开内联编辑后，用卡片真实 `getBoundingClientRect().height` 再 place 一次。  
- 弱反馈达阈值前可做极轻提示（可选）：词下划线变淡一档，或设置页统计「本周自动少标 N 词」。  
- 统一命名：卡片「继续提醒」= 设置「总是提醒」→ 建议统一为「总是提醒」或「别再藏这个词」。

### 4.3 漏词与查词一致性

| 入口 | 结果形态 | 可做动作 | 不一致点 |
| --- | --- | --- | --- |
| 标注词 tooltip | 词 / 音标 / 中文 / 认识 / 更多 | 认识、继续提醒、改释义 | 完整 |
| 选词 / 右键 | 同 tooltip | 同上 | 好 |
| popup 快速查词 | 词 / 音标 / 中文 / 标为认识 | **无继续提醒、无改释义** | 与页面卡片能力不对齐 |
| 缺词 tooltip | 联网查询 | 成功后进完整卡 | 关闭联网时文案尚可 |
| 联网失败 | 入队 + 文案 | popup 底部有摘要 | 点摘要只 `openOptionsPage()`，**不锚到重试队列** |

**可优化方向**

- popup 查到词后：次要链接「改释义 / 打开完整卡片语义」或至少「在设置中编辑」。  
- `openOptions('#section-privacy')` 或 `#online-retry`，并在 options 启动时 `scrollIntoView`。  
- 失败态固定句式：`查不到 · 已安排稍后重试 · 查看队列`。

### 4.4 「标太多 / 标太少」多旋钮问题（仍是核心心智债）

当前仍同时存在多层控制：

| 旋钮 | 作用域 | 入口 |
| --- | --- | --- |
| 初始词汇水位线 | 全局 | 设置 · 阅读 |
| 标注密度 | 全局 | 设置 · 阅读；popup 条件按钮；「少标一点」二次效果 |
| 站点模式 low-density / safe / manual / paused | 站点 | popup 三主按钮 + 高级五模式 |
| 标注策略 suppressionMode | 全局弱反馈节奏 | 设置 · 策略（文案「少标一点」与 popup 同名） |
| 单词 known / skip / alwaysAnnotate | 单词 | 卡片 / 设置策略 |

**冲突示例**

1. 设置策略里的按钮文案也是 **「少标一点」**（aggressive），与 popup 站点任务按钮同名，**不是同一动作**。  
2. popup「少标一点」在已是 `low-density` 时会改 **全局密度**，用户以为只影响本站。  
3. 「本页工具」里的「再少标一些 / 多提醒一点 / 恢复平衡密度」与三主按钮职责重叠，条件触发时突然多出按钮，**同一任务多入口**。  
4. 「更稳一点」与「切到仅手动查词」（诊断建议）语义接近，步进规则不完全一致。

**目标心智（建议写进产品说明）**

```text
先问：是「这个站」还是「所有站」还是「这个词」？
  这个站 → popup 三按钮
  所有站 → 设置：水位线 + 密度 + 策略节奏
  这个词 → 认识 / 总是提醒 / 恢复提醒
```

**可优化方向**

- 设置策略文案改名：如「更快少标重复词 / 更久保留提醒」，避免与 popup「少标一点」撞车。  
- 「少标一点」若触及全局密度，状态提示写清：`已降低全局密度（所有网站）`。  
- 收敛本页工具里的密度快捷键：能被三主按钮覆盖的不再并列出现，或明确副标题「微调全局密度」。

### 4.5 站点模式状态机边界

当前三主按钮逻辑（代码）：

| 当前模式 | 少标一点 | 更稳一点 | 暂停 |
| --- | --- | --- | --- |
| auto | → low-density | → safe | → paused |
| low-density | 降全局密度 | → safe | → paused |
| safe | → low-density（回退感） | → manual-only | → paused |
| manual-only | → low-density | → manual-only | → paused |
| paused | → low-density | → safe | 保持 paused |

**体验问题**

1. **暂停后仍显示「少标 / 更稳 / 暂停」**，点「少标」会离开 paused 进入 low-density，可能不符合「我只是想先停一下再微调」的预期。暂停态更合理的主操作只有「恢复自动」。  
2. 从 safe 点「少标一点」会回到 low-density（标注变多的方向），与按钮语义相反。  
3. paused 与 manual-only 的差别（是否响应手动查词）仅在折叠说明和诊断文案中，主按钮区无对照。  
4. 状态卡「恢复自动」很好，但高级区五模式与任务按钮**双向可达**，容易改乱后不知道该看哪一行。

**可优化方向**

- `paused`：隐藏或禁用少标/更稳，只留恢复；或点少标时二次确认「将结束暂停并进入少标模式」。  
- 为三按钮增加 `disabled` + title：已到终点时说明「已经是最稳：仅手动」。  
- 当前模式行增加一句人话：`暂停：不标注也不查词` / `仅手动：不划线，仍可 Alt 查词`。

### 4.6 Popup 交互细节

| 问题 | 说明 | 严重度 |
| --- | --- | --- |
| 全量 `innerHTML` 重渲染 | 每次状态变更重建 DOM，查词输入框易丢焦点/光标 | 中 |
| 折叠状态仅内存 | 关闭 popup 后高级区/诊断展开态丢失（可接受） | 低 |
| 不可读页 | 诊断空时有提示，但重扫可能无效且无「权限/chrome 页」人话 | 中 |
| 复制反馈 vs 复制诊断 | 主路径只露「复制反馈」，诊断在折叠内——合理 | — |
| 联网重试按钮 | 0 条时仍可点进设置，略空 | 低 |
| 首屏高度 | 四段面板 + footer，小屏笔记本仍可能要滚一点 | 低～中 |

**可优化方向**

- 查词区局部更新，避免整页 re-render；或 re-render 后恢复 `lookup-input` 焦点与选区。  
- chrome://、扩展商店、PDF 查看器等：状态卡直接说「此页浏览器不允许扩展读写」。

### 4.7 设置页信息架构与任务完成度

| 项目 | 现状 | 体验问题 |
| --- | --- | --- |
| 四锚点导航 | 有 | 仍是长页滚动，不是真正分区隐藏；锚点点击后 **无 active 态** |
| 学习回顾 | 三张卡片 | 信息量少（各 1 词），「最近查过」无动作，「查得最多」才能标认识 |
| 词表检索 | 过滤生词/熟词 | **不过滤自定义释义列表**（自定义面板独立） |
| 自定义释义 | 完整 CRUD | 与「释义不准」无「刚改过的词」高亮回链（hash 到 `#custom-dictionary` 未从 tooltip 打通） |
| 导出 | 生词区多格式 + 隐私完整备份 + 一句说明 | 说明有了；**导入仍 confirm 二选一**，无「将写入 N 项」预览 |
| 触发方式 | 悬停/点击两按钮 | 无「路过就弹？改点击」解释句 |
| 策略区 | skip 列表最多展示 6 个 | 超过 6 的词难发现；重置弱反馈无二次说明影响范围 |

**可优化方向**

- 锚点导航：`IntersectionObserver` 高亮当前组；可选「只显示当前组」减少滚动疲劳。  
- 学习回顾扩展为可点列表（最近 5 / 高频 5），并支持「标认识 / 打开释义编辑」。  
- 检索框作用域写清，或一搜三表（生词+熟词+自定义）。  
- 导入预览：`生词 N · 自定义 M · 站点策略 K · 画像 1`。

### 4.8 弱反馈与「越用越准」的可解释性

弱反馈是产品差异点，但当前对用户几乎是黑盒：

```text
标注出现在视口
  → 用户未交互超过 skipDelayMs
  → familiarity++
  → >= skipLimit 后不再标注
  → 用户无通知
```

| 问题 | 影响 |
| --- | --- |
| 无「为什么这个词消失了」解释 | 用户调密度/水位线瞎试 |
| 策略「多提醒我/平衡/少标一点」偏抽象 | 与站点「少标」混淆 |
| 恢复入口在设置深处 | 发现成本高 |
| 卡片无「我觉得不该消失」入口 | 只能靠「继续提醒」预防，无法事后在页面上找回 |

**可优化方向**

- 设置策略面板顶部增加人话：`路过未点开 N 次后，会暂时不再标注；可在下方找回。`  
- popup 诊断：当本页扫描段多但标注少且存在 weak-hidden 统计时，提示「有些词因「已路过多次」被收起 · 去设置恢复」。  
- （可选）在释义卡更多菜单增加「为什么会出现这个词」一句（水位/密度/总是提醒）。

## 5. 交互逻辑层面的结构性问题

### 5.1 状态维度过多

用户状态可同时被这些维度调制：

`level × density × siteMode × suppressionMode × wordState(known|skip|always) × lookupTrigger × onlineEnabled`

对开发者合理；对用户过载。**产品上需要「推荐入口」而不是「暴露全部自由度」。**

### 5.2 全局副作用藏在站点动作里

`resolveLessAnnotateAction` 在 low-density 下修改 **全局** `annotationDensity`。  
这是隐蔽的跨作用域副作用，违反「一次一事 / 可解释」。

### 5.3 渲染即状态机打断

popup `renderPopup` 全量重建会导致：

- 输入中的查询被重绘打断  
- 展开态依赖外部布尔位（已处理）但焦点不能  
- 未来若加 toast/动画会更痛  

### 5.4 反馈写入与 UI 可见性不对称

| 写入 | 用户可见性 |
| --- | --- |
| known | 高（去标注 + 撤销） |
| alwaysAnnotate | 中（确认条） |
| lookup → vocab | 中（设置回顾） |
| skip familiarity | **低** |
| online cache | 低（来源 pill） |
| site policy | 中（本站现在：） |
| density from popup | 中（状态消息，但作用域易误解） |

| --- | --- | --- |

## 7. 建议的下一轮体验原则（实施时过滤用）

1. **作用域外显**：任何按钮副作用必须能用「本站 / 全局 / 本词」三个词之一说清。  
2. **同名同事**：同一中文标签禁止绑定不同状态机。  
3. **暂停是特殊态**：暂停态主路径只有恢复，不混用调节按钮。  
4. **消失可解释**：自动少标（弱反馈）必须能在一处被看见、被撤销。  
5. **跨页带路标**：从 A 界面跳到 B，必须落到对应锚点/高亮项。  
6. **少入口**：同一用户任务最多一个主入口 + 一个高级入口。  
7. **文档跟界面**：README 与界面同步视为体验缺陷，不是文档债。

## 8. 建议实施分期（供确认，不自动开工）

### 阶段 IX-0：文案与作用域澄清（低风险，高收益）

- 统一：总是提醒 / 别再藏这个词；站点「恢复自动标注」；单词「取消固定提醒」。  
- 策略 aggressive 去掉「少标一点」撞车文案。  
- 「少标一点」触及全局密度时状态句写明「全局」。  
- 同步 README 主路径与 popup 三按钮。  

**Done-means**：相关单测文案断言更新；`typecheck` + 受影响 vitest 通过。

### 阶段 IX-1：状态机与入口收敛

- paused 主操作收敛。  
- 理顺少标/更稳步进，避免「更稳后再少标变多标」。  
- 收敛本页工具与三按钮重复项。  

**Done-means**：popup 单测覆盖 paused/safe 边界；手动剧本 B 通过。

### 阶段 IX-2：可解释的弱反馈

- 策略区人话 + 计数。  
- 可选：popup 提示「有词因路过被收起」。  
- 恢复入口可达性提升（从 popup 深链到策略区）。  

**Done-means**：至少一条单测或组件断言覆盖新文案/入口；不改变 skip 算法默认参数 unless 明确要求。

### 阶段 IX-3：跨界面导航与一致性

- options hash 启动滚动与高亮。  
- 重试队列 / 自定义词典深链。  
- tooltip 真实高度重定位。  
- popup 查词局部渲染或焦点恢复。  

### 阶段 IX-4：触控、导入预览、回顾加厚（抛光）

- 粗指针 → 提示或自动 click。  
- 导入预览计数。  
- 学习回顾列表化。

## 9. 验收剧本（回归 + 新增）

### 剧本 A：新用户 1 分钟

1. 安装 → 开英文页 → 点图标  
2. 3 秒内知道是否在工作  
3. 不进设置也能少标 / 重扫 / 查词  
4. （目标）能发现「安静阅读」或触发方式说明  

### 剧本 B：标太多

1. 连点「少标一点」  
2. 能理解第一次是本站模式、第二次是否影响全局  
3. 暂停后再打开 popup，不会误触离开暂停  

### 剧本 C：释义不对

1. 更多 → 改释义 → 保存  
2. 再打开同词已是新释义  
3. 展开编辑时卡片仍完整可见  

### 剧本 D：词突然没了

1. 用户能在设置策略看到「被收起的词」  
2. 一键恢复后页面重扫可见  
3. （目标）popup 或策略有一句原因  

### 剧本 E：换机

1. 导出完整备份  
2. 导入前看到将写入的数据规模  
3. 生词与自定义仍在  

### 剧本 F：平板

1. 默认或提示下可用点击查词  
2. 卡片按钮可点中，不会因无 hover 无法打开

## 12. 结论

潜词在 **「安静标注 + 短释义 + 可撤销认识」** 主路径上已经可用，上一轮 popup/释义卡/设置导航改造解决了「功能堆满首屏」的主要矛盾。

当前体验债的重心已经转移为：

1. **多旋钮同名不同义**（少标 / 恢复自动 / 继续提醒）  
2. **全局副作用藏在站点按钮里**  
3. **弱反馈不可解释**  
4. **跨界面跳转无路标**  
5. **触控与首启引导仍弱**  
6. **文档滞后于界面**

建议下一轮以 **IX-0 文案作用域 + IX-1 状态机收敛** 为优先；它们不扩权限、不改架构，却能明显降低「我点了这个会怎样」的不确定感。功能继续堆叠的边际收益已低于把现有交互说清楚、走顺畅。
